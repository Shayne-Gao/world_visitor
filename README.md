# Changelog - 世界迷雾 Web (Fog of World Web)

本项目旨在打造一个**完全本地优先 (Local-First)**、可终生记录并运行 30 年的个人地理空间数字资产系统。

---

## [v0.1.33] - 2026-04-23
### 🗺️ Map Layers (极致偏移对齐修复)
* **重构地图投影纠偏架构**：彻底解决了上一版本引入的“按下葫芦浮起瓢”的多图层投影冲突问题。现在无论是街道模式、卫星模式还是混合模式，在中国大陆以及海外均能完美对应实际地理位置。
  * **方案 A：针对基础街道图 (高德、谷歌街道)**。恢复并稳固了对 Leaflet 全局 `project` 的拦截。这能保证在纯 GCJ-02 模式下，所有的瓦片以及用户绘制的 WGS-84 轨迹向量，都能被物理投射到完全一致的火星坐标系位置，实现了丝滑且严丝合缝的对齐。
  * **方案 B：针对谷歌混合图 (Google Hybrid)**。废弃了复杂的底层类继承，改用更为安全轻量的“CSS 视觉偏移法”。由于混合图的底层必须是纯净的 WGS-84 卫星图（不能扭曲），我们通过 `map.on('move')` 实时计算当前屏幕中心的 GCJ-02 与 WGS-84 的绝对像素差值，然后以极其丝滑的性能将上层的街道名称标签图 (Label Layer) 推回到正确的视觉位置上。这种双管齐下的方案彻底隔离了不同图层类型的纠偏冲突。

## [v0.1.32] - 2026-04-23
### 🗺️ Map Layers (终极投影隔离重构)
* **解决混合模式下单图层独立偏移难题**：彻底解决了 Google Hybrid 图层中“底层卫星图不需要偏移，但上层叠加的街道注记必须单独进行 GCJ-02 偏移”的冲突问题。
  * **技术突破**：此前我们直接在 Leaflet 全局的 `L.Projection.SphericalMercator.project` 中注入了偏移逻辑，导致同一时刻屏幕上渲染的所有图层要么一起偏移、要么全不偏移。由于 Leaflet 不支持单地图多 CRS（坐标参照系），我们在本次更新中引入了名为 `L.TileLayer.Gcj02` 的定制类。
  * **投影上下文劫持**：该类会在向服务器计算每一块需要偏移的瓦片行列号（x, y）的瞬间，短暂“劫持”并开启全局偏移上下文 (`isProjectingGcj02Layer = true`)，算完立即关闭。
  * **完美兼容**：现在你可以放心使用 Google Hybrid 模式。底层的卫星图 (`lyrs=s`) 依然使用原生类进行渲染保持 0 偏移，而上层叠加的透明街道名 (`lyrs=h`) 以及其他独立街道图（如高德），则会通过新的类自动进行精准偏移对齐。

## [v0.1.31] - 2026-04-23
### 🗺️ Map Layers (地图源优化)
* **重构谷歌混合地图 (Google Hybrid) 底图逻辑**：解决了在 Google 混合模式下，“卫星底图坐标正确，但上层叠加的街道和地名标签偏移”的视觉割裂问题。
  * **技术细节**：原先使用的 `lyrs=y` (Hybrid) 瓦片是谷歌服务端预渲染好的一体化图片，由于中国大陆地区的政策限制，谷歌在服务端强制将街道标签套用在未偏移的卫星图上时产生了物理偏移，前端无法通过坐标转换将其分离。
  * **解决方案**：放弃使用预渲染的 `lyrs=y`，改用 Leaflet 的 `L.layerGroup`。底层铺设原汁原味的无偏移卫星图 (`lyrs=s`)，上层叠加谷歌纯透明的独立街道标签层 (`lyrs=h`)。通过前后端图层分离，彻底解决了混合图层中“图文错位”的问题，现在混合模式下的所有道路名称将与真实的卫星地形完美贴合。

## [v0.1.27] - 2026-04-23
### 🐛 Bug Fixes (缺陷修复)
* **国内底图坐标偏移未生效修复**：彻底修复了在上一版本中引入的坐标转换未能按预期工作的核心 Bug。
  * **问题原因**：原先覆盖的是 Leaflet 的 `L.CRS.EPSG3857.project` 方法，但在 Leaflet 的底层渲染管线中，将经纬度转换为屏幕瓦片坐标时，直接调用了更底层的 `L.Projection.SphericalMercator.project`，导致原先的覆盖代码被完全绕过，偏移逻辑如同虚设。
  * **解决方案**：将拦截层下沉至最底层的 `L.Projection.SphericalMercator`。如今地图在渲染任何带有火星坐标系的瓦片时，能真正同步将用户绘制的轨迹一并施加投影偏移，实现了完美的严丝合缝。
* **精准作用域控制**：根据需求，严格限定偏移逻辑的触发条件：仅当你在**中国大陆境内**且当前选择的是 **高德街道图 (AMap)**、**智图 (GeoQ)** 或 **谷歌街道图 (Google Street)** 时才会触发火星坐标修正；如果你使用卫星图或 OSM，亦或者身处新加坡等海外地区，逻辑会自动休眠，确保海外体验原汁原味，不差毫厘。
* **图层切换平滑防跳动**：由于引入了动态投影，原先切换图层时会由于底图的物理坐标差异导致画面瞬间跳跃。现已补充 `map.setView()` 重算像素基准的逻辑，图层切换现在像丝般顺滑。

## [v0.1.26] - 2026-04-23
### 🗺️ Map Layers & Coordinate System (地图源与坐标系适配)
* **新增国内可用地图源**：为了解决国内网络环境无法加载谷歌底图的问题，在图层菜单中新增了**高德地图 (AMap)** 和**智图 (GeoQ)** 两个国内极其稳定、加载迅速的地图源。
* **动态火星坐标系 (GCJ-02) 偏移修正**：彻底解决了在中国大陆区域内使用谷歌地图或高德地图时出现的“定位漂移”和“轨迹偏离道路”问题。
  * **核心原理**：底层 IndexedDB 和核心业务逻辑坚持只存储和使用全球通用的纯净 WGS-84 坐标系。
  * **按需投影**：通过重写 Leaflet 的底层投影方法 (`L.CRS.EPSG3857.project` 和 `unproject`)，系统会在渲染时实时判断：如果当前坐标落在中国大陆范围内（通过精确的边界算法检测），**且**用户当前选择的是带有火星偏移的底图（谷歌系列、高德、智图），系统才会**动态在内存中**将其转换为 GCJ-02 坐标交给 Canvas/SVG 渲染。
  * **无损回写**：当用户在偏移的底图上手动标记时，系统会自动将屏幕上的点击位置 (假 GCJ-02) 反算回真实的 WGS-84 坐标并入库。这保证了无论用户切换到什么底图（比如未偏移的 OSM），之前画的轨迹永远能精准重合，实现了“一份真实数据，完美兼容全球任何标准的地图源”。

### 🐛 Bug Fixes & Stability (稳定性修复)
* **自动追踪“防飞线”机制 (Anti-Flying-Line)**：彻底修复了移动端锁屏、切后台导致 GPS 中断后，重新唤醒时与上一个坐标连成穿墙长直线（飞线）的致命 Bug。
